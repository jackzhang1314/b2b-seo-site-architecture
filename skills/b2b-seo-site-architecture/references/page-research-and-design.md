# 竞品逐页拆解、工厂表达与设计简报

## 目标与业务角色

本Skill主要服务外贸工厂和外贸企业。工厂身份、制造能力和采购信任信息是核心研究主线，要贯穿首页、About Us、类目及产品页，不只在某个角落放一句“厂家”。先从已提供资料核实实际角色：制造商、贸易商、工贸一体或未知。对真实工厂设计清楚的工厂表达；贸易商呈现其实际采购、供应链、质检与服务能力，不能包装成自有工厂。用户群以工厂为主，不等于每个客户都已证实拥有工厂。

研究“最适合这家企业和目标采购者的方案”，不宣称找到了普适最佳布局。不能把竞品模块的并集当作完整方案，或把有排名/流量归因于某一个模块。每个采用模块说明解决什么采购疑问、依据和企业需要提供什么证据。

## 逐站、逐页研究，按问题回访

1. **建立覆盖清单。** 用户列出的竞品站点逐站登记。根域名先展开核心页面清单；明确提供的核心URL逐页登记，不能只保留网址。首页、About Us、联系、主类目与产品详情，以及实际存在的制造/工艺/质控/证书等页都需考虑，即使它们不是最高流量页。大量排名URL保留全量关联；同型页面可记录代表样本和未逐页范围，不能把抽样写成全量。
2. **第一轮完整拆解。** 用Computer Use打开菜单和核心页，滚动到页尾，记录模块顺序、内容任务、布局、可见字段、图片/证据、CTA、内部入口与交互状态。检查代表手机布局；未观察到的尺寸/状态写未观察，不由桌面图猜测已测手机。表单只读检查，不默认发送。截图或观察文件保存到当前客户项目，可对应URL和时间。
3. **按页型横向比较。** 比较同类页面怎样解释业务、展示产品/制造能力、证明可信度、帮助选型和收集询盘。区分“普遍但无价值”“必要且有依据”“对本站有用的差异”“本站不具备的能力”，再组织本站模块。竞品原文、图片、认证和客户标识不能变成本站资料。
4. **针对缺口回访。** 出现字段不明、模板边界矛盾、证书适用范围不清或页内交互未看完时，返回相关URL；必要时补充不同业务角色的可比样本。记录第几轮、发现、决定变化和剩余问题。不是为了凑轮次机械刷新相同页面，也不能用一次首页浏览代替全部研究。
5. **明确停止条件。** 本轮核心URL均已处理，所选模板/必要变体有研究或业务依据，核心采购问题有模块承接，字段和缺口已记录后交接。受阻或缺企业事实时给暂定方案与最小补数任务；覆盖不足仍标部分完成，不能为了交付改成“已完成研究”。

## 中间过程必须落地为本地Markdown

每完成一站或一轮，把发现及时更新到客户项目的调研Markdown；不要等最终HTML才补一篇泛泛总结。复用现有报告入口，保留历史轮次与改变理由。推荐同一阶段维护一个`research-report.md`，资料量大时按站拆文件并提供索引。

报告至少包含：

- 输入/业务角色和研究范围；全部目标URL、已访/部分/受阻/未访及时间。
- 每个URL的页型、导航位置、采购任务、从首屏到页尾的模块顺序。
- 每模块的内容与可见字段、桌面/手机布局观察、图片及证据类型、CTA和交互。
- 同页型横向比较：采用、改造、不采用及原因；工厂表达是否符合本站实际角色。
- 每轮回访的问题、发现和调整；模型建议与观察事实分开。
- 本站核心页和模板决定、模块/字段设计、尚缺素材及下一步。
- 原URL、来源、截图/本地观察文件，足以回查。只有搜索摘要或抓取内容不能冒充Computer Use实访。

脚本可以把已经记录的研究汇总成Markdown；不会自行访问网页或证明这些记录真实。

## 工厂信息怎样放到不同页面

| 页面 | 应回答的采购问题 | 适用内容与证据 |
| --- | --- | --- |
| 首页 | 你生产什么，适合哪类买家，为什么值得继续了解 | 首屏明确实际制造/供货角色与产品范围；产品入口；简洁制造流程或工厂实景；关键质量/交付证据；联系入口 |
| About Us | 企业和工厂是谁，业务边界与合作对象是什么 | 主体与品牌关系、地点和真实厂区/团队、自产/采购/外协边界、业务历程与可核事实；避免只有口号或老板致辞 |
| 一级/二级类目 | 这一产品系列怎么选，工厂能怎样供货 | 产品范围、型号/规格比较、与该类目有关的制造和质检、配置/定制边界、相关证书/资料、交付问题；不要整段复制About |
| 产品详情 | 这个具体型号能否满足要求，谁制造、怎样保证和交付 | 型号身份、图片与规格单位、配置/适用边界、对应工艺/检测、型号相关报告/手册、包装与询价字段；不把通用证书写成所有产品认证 |
| 制造能力/工艺 | 哪些步骤自己做，设备与过程能支持什么要求 | 过程及输入/输出、真实现场图/设备、产能统计口径与条件、外协边界、工程与样品流程；数量未知不填零或虚构数值 |
| 质量控制/证书资料 | 检查什么，谁负责，有什么可核文件，适用哪些产品和市场 | 来料/过程/出厂检查、检测项目和记录、追溯方式；证书主体、类型、机构、编号、有效期、适用范围与文件；缺证书则列资料请求或待补，不画假徽章 |
| 联系/询价 | 如何联系，交哪些资料，提交后会发生什么 | 实际地址和渠道、产品/型号/数量/目标市场/规格或图纸、适用附件条件、隐私和反馈；仅在有真实政策时承诺响应时间 |

以上是研究问题，不是每站都要独立建出的页面清单。按行业、采购复杂度、真实业务与资料量决定独立页、同页模块、模板变体或暂缓：例如CNC可研究材料/工艺/检测，机械可研究装配/功能测试/交付，电子可研究生产/测试/适用合规；具体项目以实际证据为准。证书少或不能公开时，不为凑页数建立空证书中心。

## 完整页面与模板设计简报

每个核心页、独立设计页及模板代表页需要足够信息让下一步AI画出完整页面：

- 读者、页面目标、首屏核心信息、文案方向、页面独有内容、主要CTA。
- 全站共用的页头/页脚、视觉方向、字体层级、留白/密度、图片风格及手机导航。
- **有顺序的模块规格**：解决的问题、必须包含什么内容、桌面/手机布局、图像及交互/空态、必需或启用条件、适用变体、关联字段与取舍证据。
- **字段字典**：可读名称、类型、全站/单页/多条记录范围、必填/可选、格式/单位/图片比例/重复结构、真实资料来源、提供状态及缺失处理。此处是内容字段设计；CPT/ACF key与实际保存方式在客户工程中核定。
- 工厂证据在本页的具体作用；没有证据时使用待补标记、合适占位或不展示，不把占位当成发布文案。
- 同模板不同页面的内容变化；必要变体的代表页；不为每篇文章做一张新模板图。

设计任务覆盖完整长页，不能只写首屏或“Hero—优势—联系”这类空泛标题。必要模块完整不等于信息全部默认展开：把次要详情折叠或分层，让用户先看到选择与行动所需的内容。

## 最终HTML要简洁、可直接交设计

主入口展示核心架构、页面设计简报、模板、菜单与独立文章计划。点击首页、About Us、联系、类目或产品代表页，可以看到该页完整模块顺序与内容要求，再展开字段和依据。研究过程放Markdown，HTML只显示关键取舍、来源和覆盖，并链接本地报告。

提供可复制的完整单页设计任务，包含页面信息、适用模块、字段、工厂证据与素材缺口；避免让用户手工从多个表拼装上下文。AI生成设计图后仍需按这些要求验收完整性和事实准确性，不保证仅凭架构就自动获得最佳视觉效果。
