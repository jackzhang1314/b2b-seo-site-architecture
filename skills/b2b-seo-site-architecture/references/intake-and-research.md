# 输入与竞品实访规范

## 四类原始资料，Codex聚合与核对

标准入口是用户从Semrush/Ahrefs等工具导出的产品种子拓词表和竞品排名关键词—URL表，加竞品名单与企业资料。种子如`excavator`、`digger`，各自扩展包含产品词及明确词形变体的关键词。用户不必先把两类表手工合成行业词库。接收现成Excel/CSV、文档、产品目录和网址；已有词库/聚类可复用。缺项时先按[补数引导](data-collection-guide.md)说明当前最小任务，不以资料不全为由直接结束。

| 资料 | 最小有用内容 | 缺少时怎样处理 |
| --- | --- | --- |
| 本企业业务范围 | 实际经营产品/服务、型号/材料清单、市场/语言、客户与询价方式；经营与不经营的边界 | 未确认业务不进入正式导航；可先列待核节点 |
| 产品种子拓词表 | 种子词、拓展关键词、目标国家、来源工具/日期；保留搜索量、难度、意图等已有列 | 可逐种子导出再由Codex合并；只给种子时引导取得实际拓词表，不用模型扩词冒充工具数据 |
| 竞品名单 | Top20及补充的低DR/少外链但相关流量高的网站，名称/域名/分组/入选理由；有DR或其他权重指标、引用域、相关流量等就保留 | 名单可约30站，不定额凑数；可从排名表域名恢复名单，已知信息不重复索取 |
| 竞品排名关系 | 域名、关键词、排名位置1–30、对应排名URL、国家、数据日期；保留搜索量和逐词估算流量等已有列 | 没有URL就不能完成页面承接研究；缺流量仍可分析排名可见度，不将缺失补零 |
| 现有网站/旧方案 | 改版时的URL、页面内容、已有导航与可得表现 | 新站可没有；旧站缺表现时不推定内耗或授权改URL |

开始后给出简短接收说明：各原件及行数、市场/语言、排名范围、导出是否受限、哪些缺项影响正式决定。此工作流的前30明确为排名位置1–30的全部可得词，不是每站挑选30个词。字段能从原件确定就自行映射；只询问实质影响架构的未知项，同时继续其他分析。资料不足时交暂定方案、缺口及当前补数任务，不能把受阻研究标成完整交付。

一份竞品排名导出可同时产生词库和“关键词—域名—排名URL”关系，无须用户重复整理两份。相同词跨竞品/URL/日期的关系不因词库去重被抹去。排名URL应保留原值、访问后的最终URL和访问状态；跳转到泛目录不等于原细分页仍存在。

行业词库＝种子拓词＋竞品排名1–30的关键词，按相同市场/语言去重后再做业务审阅。竞品词不再强制要求包含种子词，以免丢失材料、型号、应用或采购问题。原件完整保留，品牌、无关行业、非经营业务等词通过审阅说明取舍，不无痕删除。输入若超过工具导出上限，按已得到的范围工作，不把受限导出称为整个市场的全部关键词。

名单保留两类竞品的入选理由。低DR/少外链与高相关流量是研究线索，不能推出架构是流量增长的唯一原因；核对是否主要来自品牌词、不相关主题或异常单页。DR、DA和其他工具权重分开记名称/来源，不互换；外链条数、引用域数量、域名权重和页面本身获得的链接也分别看。没有指标时标“用户提名、指标待核”，不伪造筛选通过。

词频默认按同市场/语言的去重关键词计算；不能直接拼接多个竞品表，把来源重复当成需求频次。竞品覆盖次数可另算，但不替代TF/DF。核对行业词库是否已包含排名表中的词；若有缺项，可保留来源补入并说明数量，不让用户重新手工合表。

如果输入声称“排名位置1–30”，逐行检查范围：31位等超范围行和缺排名/URL行保留在接收问题表，分别标明；不能凑成已核Top30证据，也不能把缺URL填成竞品首页。当前不足不阻止其他有依据的分析。

对`2 ton / 2-ton / 2t / 2000 kg`等形式，原始词频不偷偷合并；另用明确词典或解释记录将它们归入重量维度。词序、连字符写法可结合上下文判断，数值与单位换算必须核对吨制、产品系列范围和参数定义。没有依据时可发现候选，但保留归属待核，不自动把它们全部分配到2 Ton页。

若确实要补SEO数据，一次给一个可执行任务：已知授权入口、报告、国家、筛选和必要字段、回传原文件方式。导出受限时接收可见截图并记录范围。无需用户安装MCP、购买服务或按JSON填表。

## 两条研究线

万级词库按[脚本工作流](large-keyword-workflow.md)全量接收、去重和统计；模型负责实体/采购任务、属性用途和页面边界判断。用户提供更广排名范围或全部有流量URL时完整保留，不再要求截成1–30；Top30只作为独立统计视图。Top Pages页面流量与逐词流量分开，商业页和博客页都进入研究清单与对应规划。

**需求线：** 先把每条长关键词拆成单词，单独输出一词词频，再计算2–3词词组TF/DF。TF是单词在词库文本的总次数，DF是包含它的关键词条数；保留“原词→拆词”的示例。用`ton`发现吨位维度，回查`1 ton`、`2 ton`、`3 ton`形成候选类目，再关联各自的原关键词、竞品排名URL与观察到的页型。桶类、工况、材料等用同样方式处理。采用去重后同口径词库；竞品出现次数另算。Codex据此提出产品/材料/工艺/应用/供应/比较等维度，再按采购任务语义分组。宽词、低量词和无量词不自动剔除；同词形不同市场/语言不偷偷合并。已有合理分组直接复用，重点复核影响页面拆合的边界。

**页面线：** 每个竞品先标明是同类供应商、品牌厂商、平台还是内容站。通过实际Computer Use观察：

1. 顶部导航和相关下拉/折叠菜单、页脚入口；标签是否有独立目标。
2. 核心一级类目、子类目、目录和详情页，记录面包屑及父子入口。
3. 排名关系表中高业务价值、覆盖不同需求/页型或影响拆页决定的URL，打开核标题、页面任务和核心模块；其余记录为未逐页回读。去重URL后研究可避免重复打开。
4. 动态筛选、系列选择、比较、下载、询价等：判定是在同页改变状态，还是进入独立页面；只作只读研究，不发送表单。

在逐词关系表之外做“竞品排名页汇总”：每个URL汇总同来源/市场/日期的排名词、需求组、最佳排名和范围内估算流量，关联实访页型、导航位置、模块及采用/不采用理由。保留数据日期与页面访问日期的区别；未实访URL只显示排名关系，不从路径直接认定页型。只有排名时只能说获得搜索可见度；有工具估算也不当作真实访问或有效询盘。

博客排名页可用于识别信息型需求，并单独形成本站文章计划。按需求/页型选重要博客代表页研究，不要求逐篇打开海量文章。用户未排除博客时可规划入口、必要分类和文章模板；全部文章标题不进入设计架构图或全站菜单。

## 覆盖记录

逐站记录域名、访问时间、菜单是否实访、代表页/最终URL、观察到的层级、页面结构、适用或不适用原因、未完成项。将来源标为 `browser_observation`、`user_provided`、`historical_sample`、`model_inference` 或 `simulation`。

页面正文会更新，公开搜索摘要可能过时；以本次页面回读为当前观察。URL失效、站点受阻、仅菜单可见等都保留实际状态。Computer Use不可用时可以继续输入整理与暂定架构，但该研究分支未通过，不悄悄用抓取结果替代。

“完整”绑定业务范围、资料和实际覆盖。名单已接收、各站代表结构已访问、各排名URL已回读是不同层级；对于20或30站均分别报告。复用历史实访时保留时间与范围，不能改称本次新访问。


## 工厂资料与核心页研究补充

外贸工厂是主要使用场景，企业资料须明确实际经营角色、自制/采购/外协范围、工厂/团队图片、工艺与质控记录、可公开的设备/产能口径、证书及其主体/产品/市场/有效期、交付与联系资料。已有材料自行核对，缺项按当前页面需要分批补，不要求用户一次填写全部字段。未知身份先保持未知，贸易商按真实能力表达。

竞品研究不能限于高流量落地页：用户给的站点逐站列核心URL，首页、About Us、联系、主要类目/详情及适用工厂能力页面均需审阅；逐页内容布局与字段观察、回访和本地Markdown记录见[详细要求](page-research-and-design.md)。
