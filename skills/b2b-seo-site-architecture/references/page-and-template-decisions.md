# 页面与模板决策

## 什么时候独立建页

综合采购任务是否独立、产品/材料实体是否有实质差异、企业是否经营、能否提供独特内容，以及相关竞品页面与适用SERP。没有固定词数/搜索量/竞品次数阈值可直接证明应该建页。

| 情况 | 优先处理 |
| --- | --- |
| supplier / wholesale / exporter描述同一产品采购入口 | 同一主要承接页覆盖相容采购问题；真实供应角色分别核实 |
| 词频发现的吨位、颜色、功率等维度 | 先列具体类目候选并回查原关键词和排名URL；有实际产品覆盖、独立任务及内容时可设细分类目，否则记录为筛选/比较或待核，不能一律认定只是筛选 |
| 型号实体不同 | 可分别建详情页，共用合适模板；未知参数标资料缺口，不抄竞品参数 |
| 材料或牌号 | 材料目录→材料类别→必要牌号详情；不是每个牌号、材料×工艺组合都建页 |
| 工况/应用 | 有明确工况约束、选择理由、推荐产品及实际能力时可建应用页；换标题复用同一正文不够 |
| 未确认的附件单卖、电动、OEM、租赁或二手 | 标待核或排除，不从竞品经营范围反推本站能力 |
| 联系、询价、公司、隐私等 | 依据业务和网站功能安排，允许无目标关键词 |

记录决策为独立页、页内章节、筛选、暂缓或排除，并说明为什么。模拟业务假设可以驱动教学方案，但须显式标识；撤去假设后受影响页应转为待核，不能冒充真实业务。

## 三种结构分别维护

英文站的页面和菜单以英文主名、中文辅助翻译交付，遵循[英文层级与属性规范](language-hierarchy-and-attributes.md)。多个应用详情应有真实Applications/Industries集合页；例如Landscaping与Trenching归Applications，产品系列归Mini Excavators。菜单分组不代替集合页，增加父级也不等于自动修改旧URL。

- **页面父子树：** 表达内容的主要归属和计划面包屑，每个真实页面有一个主要父级。跨应用推荐同一产品时引用同一页面，不复制产品URL。
- **导航：** 从任务出发选择菜单入口；可有无独立URL的菜单组。下拉深度不自动等于网站全部层级；深层型号通常通过目录到达。
- **URL：** 易读、稳定、符合现状。页面树有三级不意味着必须三段路径；旧URL不得为了看起来整齐就擅改。筛选参数与页内锚点默认记录为状态，不自动成为规划页。

一级类目总览通常解释范围、展示子类入口；二级选型页通常展示型号比较、筛选与选型约束。若只有一条产品线、没有真实子类，不为凑层级增加空Products页。

## 设计架构图与文章计划分开

本图用于下一步设计菜单、核心页面和可复用模板，不是全站所有内容URL的展示清单。博客从开始即可规划，表达方式如下：

- **核心架构图：** 博客入口，以及确有需要的选型指南、维护知识等分类入口；不列每篇文章标题。
- **导航方案：** 博客/资源入口，必要时加入主要分类；单篇文章通过列表、分类、搜索或正文链接到达，不逐篇进入全站菜单。
- **模板清单：** 博客列表、分类列表可按布局与字段复用或作为变体；文章详情用一个合适模板，必要变体分别选代表。文章数量不决定模板数量。
- **独立文章计划：** 选题/工作标题、需求组、主辅关键词、参考排名页、内容提纲、所属分类、优先级、CTA、事实缺口和模板。规划不代表已经写完或发布。

底层保留完整内容记录与关键词去向，输出时将`article`分到content-plan.csv；pages.csv、mindmap.md和交互架构树只含核心页。设计交接只展开文章模板的代表页；其余文章通过独立计划查看。不要用“先把文章放进图再全部折叠”代替这个区分。

## 从页面归纳模板

模板表应回答：需要设计哪类页面、由多少页面复用、页面之间哪些内容变化、设计时拿哪一页作样板。

每个模板记录：

- 编号、名称、适用页型、可复用或独立设计。
- 主采购任务、按顺序排列的核心模块、字段与交互。
- 可选模块及启用条件；如产品详情可有机器与附件变体，也可因结构和字段差异较大分为两种模板，说明取舍。
- 各实例必须独有的内容，以及禁止共用的事实字段。
- 代表页与必要变体样板；全部实例由页面表反向统计，不能手填另一份数量。
- 建议设计顺序与依赖，例如先确定分类/详情关系，再完成应用页的产品引用。

共享模块（导航、产品卡、资料下载、询价区）不等于共享整页模板。相同模板不等于相同正文。不要把所有页塞进万能模板，也不要为每个主关键词设计一套模板。

例如型号详情通常共用产品详情模板；CNC材料详情共用材料模板；一级类目总览可能与二级选型目录分开；文章共用文章详情模板。依据任务、模块、字段和交互决定，不只按URL或页面名字归类。

交给设计的每页简报至少包括：页面目标、主辅需求、主要内容区块、独特资料、CTA与目标、模板和变体、业务/内容缺口、参考证据。此阶段不要求把工程参数和最终文案全部补齐。

## 内容、布局、字段与工厂证据

从词频/关键词以及竞品筛选、规格表、对比表中归纳产品关键属性。维护一份属性表，同时决定哪些进入类目筛选、哪些要求在型号详情填写，或两处共用；明确英文名称、中文解释、类型、单位、适用范围和资料缺失处理。目录吨位等级与实际工作重量分开，缺真实值时保留字段要求并暂缓筛选，不猜数值或可用范围。

模块名称列表只是摘要。按[逐页研究与设计简报](page-research-and-design.md)为每个核心页/模板代表页补齐有顺序的内容、桌面/手机布局、图片与交互、字段类型/必填/格式/来源/缺失处理，以及本页适用的工厂身份和采购证据。不同角色与行业决定制造/工艺/质控/证书应独立建页还是进入现有页，不能默认全部建成空栏目。调研过程持续保存在本地Markdown，最终HTML按需展开详情，并给出可复制的完整画稿任务。

## 交给WordPress Builder Harness

把本轮架构与模板简报交给`wordpress-builder`入口接续：核心页/导航、模板及代表页、模块顺序、数据字段与交互、真实资料/参考页、资料缺口、验证范围和下一步。复用客户已有工作区、资料、设计和授权，不为交接重新要求用户输入同一批材料。

这里输出设计依据与模板结构规格；视觉图由Builder的设计阶段接续。按实际页面家族先设计代表页，再实现对应WordPress模板与后台编辑区。只需指出产品/材料/文章等内容类型和重复字段需求，具体CPT、taxonomy、ACF key与文件路径在实际客户项目中核定，不生成一份脱离项目的假工程配置。博客正文保留正常的文章编辑用途，不能因为规划了模板就把全部文章改成固定页面。

若用户当前只要求架构，交付后停在设计交接；不自行初始化或部署客户网站。已经明确授权后续建站时，按实际Builder入口继续，不重复询问普通开发许可。

参考方法：[Google站点结构](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure)、[URL结构](https://developers.google.com/search/docs/crawling-indexing/url-structure)。官方站点结构说明来自电商场景，此处借用页面关系与可到达性原则，不据此要求B2B网站采用购物车或零售目录。
