# 这个仓库发布哪些内容

本仓库供其他用户安装一个独立的Codex Skill。维护与实际客户研究使用各自目录。

## 纳入发布

- `skills/b2b-seo-site-architecture/SKILL.md`：执行入口与边界。
- `agents/openai.yaml`：显示名称和默认调用提示。
- `references/`：接收、研究、命名/层级/属性、规模分析、输出与设计交接规范。
- `scripts/`：四个可执行Python工具与delivery.py交付辅助模块。library.py与cluster.py来自维护者现有SEO工具并保留本包的兼容修复，随包携带，不要求用户安装另一Skill。两个脚本内部版本分别是1.1.1和1.1.2，与Skill发行版本不同。
- `examples/`：明确合成的最小有效计划和关键词CSV，用于理解字段与运行基本结构检查，不含客户资料或完整网站建议。
- `assets/architecture-view.html`：生成HTML使用的本地模板，无外部前端脚本依赖。
- 根README、版本记录、文件摘要、本说明和明确标注为MOCK的截图。

## 保留在维护环境

客户原表、公司资料、关键词与排名导出、SEO账号资料、浏览器状态、Cookie、凭据、研究截图、逐站研究、历史生成结果、原项目的Git历史、其他Skill、课程素材、缓存、日志及大规模测试数据。

回归测试依赖维护项目中的历史与合成资料，未把这些资料随用户安装包分发。不能在只有本仓库的环境中宣称重新运行了那套维护测试。公开包可用脚本`--help`、Skill格式、文件摘要、干净安装及明确的合成输入验证；业务运行仍需用户自己的资料。

## 发布步骤

1. 从已确认源码按明确文件清单复制到独立发布目录，核对实际导入与资源引用；不按目录名称误删依赖。
2. 检查Skill格式、内部链接、脚本与模板，运行受影响的回归、类型和代码检查。行为变化要检查HTML与代表输入。
3. 明确纳入路径，检查Git暂存差异；排除凭据、个人路径和未授权资料。仓库采用文件白名单忽略规则作为额外保护。
4. 更新Skill版本、README、CHANGELOG和RELEASE.json；创建新的版本标签。已发布标签不移动，旧版本保留。
5. 推送后从公开的版本标签重新安装到空目录，比较实际文件字节与摘要，并运行合成验收。不要只验证工作目录副本。
6. 交付仓库介绍链接、固定版本安装路径及实际验证边界。维护记录保存来源到远程提交/标签/ZIP的对应关系。

主分支用于当前文档与后续维护；用户安装示例固定到版本标签。更新现有安装前备份，不删除其他Skill或更改其他项目。未配置GitHub Actions时，本地检查不能写成远程CI通过。

本次未代作者选择MIT、Apache等开源许可。安装使用的分享目的不等于另行作出第三方再分发或售卖的许可承诺；如要开放这些权利，由作者明确选择协议后再更新。
